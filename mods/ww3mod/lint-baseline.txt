# WW3MOD lint baseline — the known-bad floor for `./utility.sh --check-yaml` (`make test`).
#
# HOW IT IS READ. Every error the lint emits is reduced to a signature of the form
# `<scope> | <first line of the message>`, where <scope> is the map's package folder name, or `mod` for
# the mod-wide passes. A signature listed here does not fail the run. A signature NOT listed here does.
#
# HOW TO CHANGE IT. Lowering is automatic, raising is not, and that asymmetry is the whole point:
#   * You fixed something -> the run tells you which entries no longer occur and fails until you drop
#     them. Re-run with LINT_BASELINE_PRUNE=true to remove them, and commit this file with your fix.
#     The prune path can only REMOVE lines from [repo]; it can never add one.
#   * You hit a NEW error -> the correct move is to fix it. Adding a line here is a deliberate act that
#     shows up as an added line in review; if you add one, say in the commit message why it is acceptable.
#
# SECTIONS.
#   [repo]                 Errors this repository owns. Reproducible on any checkout, so an entry that
#                          stops occurring means it was FIXED — the run enforces that this list shrinks.
#                          THIS is the number that is supposed to fall. Everything else here is noise.
#   [requires-ra-content]  Only occur where the Red Alert content is not installed. `mods/ww3mod/mod.yaml`
#                          mounts `~^SupportDir|Content/ra/v2/`, downloaded at first run; the CI runner
#                          never installs it, so every RA sprite reads as missing there and none of these
#                          appear on a developer machine that has run the game. They are matched but never
#                          required, so both environments pass. They are NOT defects and NOT lint debt:
#                          installing content in CI would delete this entire section at a stroke.
#
