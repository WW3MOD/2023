Supply trucks — what changed

2026-08-10 · autoburn window · every claim below verified by a simulation run, not by reading code
Your doctrine turned out to be already implemented and entirely unreachable. The crate, the drop-and-leave mode, and the soldiers' ability to collect from a crate all shipped months ago and were switched on. Not one crate had ever been placed, because the code that chooses where to leave it returned “nowhere” on every scan of every game. Everything else followed from that one dead function.

The five defects, in the order they were found

  1. The drop point never resolved. anchor → <none> on every scan ever run. Drop-and-leave was enabled and unreachable.
  2. Danger granted permission to abandon a delivery. Evacuation out-ranked delivery, so the truck bailed mid-run — the oscillation you were told three times was fixed. Only became testable after defect 1 was fixed: a bug that cannot fire is indistinguishable from a bug that does not exist.
  3. A 35-cell leash abandoned starving men. A full truck refused five men at 100-per-mille ammo because they were 37 cells out.
  4. The destination chased a moving platoon. A faithful 5-cell standoff, recomputed against an advancing cluster, walks the truck into the guns.
  5. Danger never selected the mode. Once the drop worked it fired everywhere, dumping crates on undefended fronts and emptying trucks that had more customers.

How “is it dangerous here?” is decided

Two limbs, because each one alone was tried and failed a scenario:

  • Relative — does this cell stand out against that player's own live field. Fails alone: on a map soaked by artillery the median is enormous too, and a cell reading 462,272 was classified safe.
  • Absolute — does it exceed a figure derived from the danger unit's own definition (100 units = one believed contact at point-blank). Fails alone: this is exactly how the original thresholds broke, set for a scale that no longer existed.
  • Plus a floor, so a quiet opening reads as quiet and no crate is wasted on turn one.

The relative limb matters because the two players' median danger differs 3.4× in the same match on the same map — no single global constant can sit at the same percentile for both.

What is still wrong

fixed sinceThe starving-platoon dispersal is closed. Six ground-tasking paths could recruit a man too dry to fight — not the two the symptom suggested — and they share no base class or pool-builder, each re-implementing “own, alive, armed, mobile, not committed” from scratch. That is how a skip-out-of-ammo check came to exist on three of them and not the other three. A single shared gate now excludes a unit below the starving threshold from combat tasking while it is dry; withdrawal, capture and walking to a crate are untouched. test-supply-far-front-reached passes for the first time.

The remaining declines were honest: six for no demand, two for the fallback-anchor stall since fixed.
The @stable benchmark baseline is now owed by three separate change sets — the danger merge, the aircraft-rearm merge, and this. The changes reach @stable deliberately (settled policy: it inherits improvements) and each commit says so, but any A/B run before a re-baseline is measuring against a control that has shifted twice underneath it.

How far to trust this

Everything above is verified on one map, one seed, five riflemen and two artillery pieces that never fire. The traces are unambiguous and the matched pair of scenarios caught two separate cases of a fix being correct alone and wrong in combination — but “green on a test bed” is not “good in a match.” The first real game you play is still the thing that decides it.
