WW3MOD — what changed since the 2026-08-02 baseline

Window: merges landed on main between the 2026-08-02 morning state and main @ fd31210d (2026-08-03). All work passed adversarial review before merge. Test suite: 650 → 742 NUnit pins over the window.

Tags mark which bot profile a change affects in a played game: EXPERIMENTAL only the Experimental AI, STABLE the Stable AI, BOTH both bots, INVISIBLE no gameplay change by design.

1. Stable bot got a big free upgrade STABLE

The Stable profile was promoted to full parity with the 08-02 Experimental build (d1b662cc, "Stable 0802"). A Stable opponent now plays with the entire influence-stack toolkit that Experimental had accumulated — expect it to be markedly stronger than the older Stable. Two genuine bug fixes also changed Stable behavior:

  • Fixed-wing aircraft recognized in squads again — an AirUnitsTypes case-mismatch made the bot treat its jets as non-air units (1c1469a8).
  • Attack helicopters are actually bought and pooled now — the heli purchase pool had a matching case bug (f05e31b7). Expect noticeably more bot air activity from both profiles.

2. Helicopters behave like a doctrine air arm EXPERIMENTAL

  • Mission system with evacuation (a9f32bcc): helis fly hit-and-run employment cycles instead of loitering; a damaged heli enters an uncancellable evacuation home; a first-contact gate stops them from wandering blind into unscouted AA.
  • Strategic-target pinning (phase 4, d2811343): once a heli squad commits to a strategic target it stays pinned for up to 1200 ticks instead of flip-flopping between targets each re-evaluation. Expect committed, repeated strikes on one objective rather than indecisive shuttling.

3. Ground force keeps its commitments EXPERIMENTAL

The recurring "my units got yanked mid-job" class of bot bugs was systematically closed:

  • Mission-commitment hold (6aff93c3, tuned to a 400-tick window in 1c1469a8): squads hold their assigned mission through a commitment window instead of re-deciding every eval.
  • Commit-on-order audit (phase 2, fd31210d): capture escorts/defenders, garrisoning infantry, transport passengers, and defence-line assignments are now all registered in the shared commitment ledger the moment they are ordered. The offense pool can no longer steal infantry that is walking to board a transport, and transport can no longer poach units another system committed. Includes a fix for commitments leaking when a carrier dies mid-pickup.
  • Quantized rival-release + aggressiveness knobs (phase 1c/1d, 1bae9628): squads release a contested objective in cleaner, less oscillatory decisions.

Net effect on-screen: fewer units dithering between jobs, capture attempts that keep their escorts, transports that complete their runs, defence lines that stay manned.

4. Combat quality EXPERIMENTAL

  • Force-preservation retreat FSM (cd396526): mauled squads pull back to preserve force instead of fighting to the last unit.
  • TECN army-share floor cap + held-axis release: capture units no longer starve the field army; a held axis frees its units when no longer contested.
  • Need-based composition buying (cbb6c023): the bot buys counters weighted by what it has actually seen (fog-legal), instead of a fixed mix.

5. Invisible by design INVISIBLE

  • Actor-name case-hardening (e73b233b): all bot-module actor-name config is normalized at rule load. Verified behavior-identical today — it exists so the next case typo becomes a non-event instead of a silent bot lobotomy (the class that caused §1's two bugs).
  • Per-unit-type telemetry (9392540c) and +tests/docs across the window.
Benchmark caveat. Because Stable itself changed this window (§1), any Experimental-vs-Stable win-rate impression from before 08-02 is invalid. A benchmark re-baseline is queued but user-gated (multi-test grant required) — until it runs, treat cross-profile comparisons as anecdotal.
