WW3MOD — what changed since the 2026-08-02 baseline

Window: merges landed on main between the 2026-08-02 morning state and main @ 39111b17 (2026-08-03, today's tip). All work passed adversarial review before merge. Test suite: 650 → 873 NUnit pins over the window (the frontline arc below added most of the recent pins).

Tags mark which bot profile a change affects in a played game: EXPERIMENTAL only the Experimental AI, STABLE the Stable AI, BOTH both bots, INVISIBLE no gameplay change by design.

★ Headline: the Frontline Influence layer (P0–P6) EXPERIMENTAL

The largest arc of the window. The Experimental bot gained an end-to-end sense of the front as a line with sectors and crossings, and now positions, attacks, and even engineers new routes against it. Six phases, all landed on main, all NUnit-pinned. Each behavior is behind its own default-off flag and enabled only in the @experimental ai.yaml block — @stable/normal/human games never opt in and stay byte-identical (zero RNG).

  • Terrain reachability model — no more "across the river = adjacent" (P0/P1, 643a2c75; P1.5, cc960ade; merge a5e22144). A map-static CrossingMap labels which cells each unit class can actually reach and finds the real river crossings. A far-bank objective is now scored by its through-crossing distance (to the nearest bridge/ford, then on), not the crow-flies distance — so the bot stops piling every axis onto one central crossing that only looked adjacent. On River Zeta this measurably de-concentrated the bot's axes onto the near-bank objectives and the enemy Supply Route.
  • Amphibious axis typing (P1). A POI its amphibious units can reach keeps full value and that axis recruits amphibious-capable units instead of stranding land units at the water's edge.
  • Forward staging + retreat damper — stop clogging the road to the front (P2/P3, 31409790; merge 3c7ee3c3). Uncommitted units now walk to a muster point a safe standoff behind the believed frontier (fanning out to avoid clogging), advancing as the front moves, rather than idling at the Supply Route. A post-retreat dwell + advance-strength floor stops small axes from ping-ponging back into the spawn bubble — without ever delaying a genuine withdrawal.
  • Frontline strength profile — sensor (P4, 55c34134; merge 62ad3908). The bot now builds a per-sector belief of own-vs-enemy strength along the front and maps which crossing opens into each sector, so it can answer "where is the enemy line thinnest, and how do I get there." No orders change in this phase — it is the input the next two consume.
  • Man-the-line + weakest-point bias + posture-hold (P5, 2b18aa02; merge 578e3770). Defensive reserves spread across the actual crossing avenues weighted by sector threat (cover every avenue first, pile surplus on the outnumbered ones). Offensively, axes aimed at the believed-thinnest enemy sector are boosted; where a sector reads too strong, the axis holds via the same retreat fall-back (placed after the genuine-retreat gate, so it can never block a losing withdrawal).
  • Engineer route-opening — open a new axis (P6, a7646012; merge 16affd44). If the thinnest enemy sector's only avenue is a repairable destroyed bridge, the bot dispatches an engineer (e6) plus a small combat screen to repair the bridge hut and open a brand-new land axis. On repair it hands the now-intact avenue back to the man-the-line / weakest-point machinery. Bounded failure handling throughout (engineer dies en route ⇒ cooldown + retry; hut gone ⇒ abandon; already repaired on arrival ⇒ success). Every dispatched unit is staked in the shared commitment ledger so the offense pool can't poach it mid-mission.
This arc is unit-tested but not yet eyeball-verified in a live game. Every phase is NUnit-pinned and passed adversarial review, and P1.5's through-crossing de-concentration was confirmed once in autotest logs — but the on-screen frontline behavior (spreading along the line, contesting flanks, sending an engineer to reopen a bridge) has not yet been watched end-to-end in a played match. It is the single most important thing to verify by eye this session.

1. Stable bot got a big free upgrade STABLE

The Stable profile was promoted to full parity with the 08-02 Experimental build (d1b662cc, "Stable 0802"). A Stable opponent now plays with the entire influence-stack toolkit that Experimental had accumulated — expect it to be markedly stronger than the older Stable. Two genuine bug fixes also changed Stable behavior:

  • Fixed-wing aircraft recognized in squads again — an AirUnitsTypes case-mismatch made the bot treat its jets as non-air units (1c1469a8).
  • Attack helicopters are actually bought and pooled now — the heli purchase pool had a matching case bug (f05e31b7). Expect noticeably more bot air activity from both profiles.

2. Helicopters behave like a doctrine air arm EXPERIMENTAL

  • Mission system with evacuation (a9f32bcc): helis fly hit-and-run employment cycles instead of loitering; a damaged heli enters an uncancellable evacuation home; a first-contact gate stops them from wandering blind into unscouted AA.
  • Strategic-target pinning (phase 4, d2811343): once a heli squad commits to a strategic target it stays pinned for up to 1200 ticks instead of flip-flopping between targets each re-evaluation. Expect committed, repeated strikes on one objective rather than indecisive shuttling.

3. Ground force keeps its commitments EXPERIMENTAL

The recurring "my units got yanked mid-job" class of bot bugs was systematically closed:

  • Mission-commitment hold (6aff93c3, tuned to a 400-tick window in 1c1469a8): squads hold their assigned mission through a commitment window instead of re-deciding every eval.
  • Commit-on-order audit (phase 2, fd31210d): capture escorts/defenders, garrisoning infantry, transport passengers, and defence-line assignments are now all registered in the shared commitment ledger the moment they are ordered. The offense pool can no longer steal infantry that is walking to board a transport, and transport can no longer poach units another system committed. Includes a fix for commitments leaking when a carrier dies mid-pickup.
  • Quantized rival-release + aggressiveness knobs (phase 1c/1d, 1bae9628): squads release a contested objective in cleaner, less oscillatory decisions.

Net effect on-screen: fewer units dithering between jobs, capture attempts that keep their escorts, transports that complete their runs, defence lines that stay manned.

4. Combat quality EXPERIMENTAL

  • Force-preservation retreat FSM (cd396526): mauled squads pull back to preserve force instead of fighting to the last unit.
  • TECN army-share floor cap + held-axis release: capture units no longer starve the field army; a held axis frees its units when no longer contested.
  • Need-based composition buying (cbb6c023): the bot buys counters weighted by what it has actually seen (fog-legal), instead of a fixed mix.

5. Air / transport polish EXPERIMENTAL

Two user-reported polish items on the Experimental air arm (merge 18ff375b, feat 92723af3); both default-off in C# and byte-identical for @stable:

  • Heli flight-path hysteresis — no more mid-flight zigzag. Attack helis used to re-issue a fresh move/attack-move path on every 5-tick re-eval, reading as indecisive. They now hold the committed leg until the recomputed destination shifts far enough (or the leg finishes). This is order-cadence only — which target is chosen is unchanged, so the first-contact AA gate, strategic-target pin, and uncancellable evacuation all still apply.
  • Fog-legal transport drop-site selection. Transports previously dropped at an omniscient "weakest enemy cell" that could sit deep behind the enemy Supply Route (one cheap unit there reads as "weakest"). Drop sites are now ranked by believed control depth, believed danger, and distance from our own Supply Route — belief-side only, never a ground-truth enemy position. It is a weight, not a hard filter.

6. Stability fix EXPERIMENTAL

Live-game crash fixed (caff1c5f). The new engineer route-opening module (P6) scanned world.Actors and read each actor's location before filtering — but non-positional actors (Player, World) have no position, so this threw a null-reference exception mid-tick and terminated the game. The scan is now trait-filtered and null-guarded first. Only reachable when playing against the Experimental bot with route-opening active.

7. Invisible by design INVISIBLE

  • Actor-name case-hardening (e73b233b): all bot-module actor-name config is normalized at rule load. Verified behavior-identical today — it exists so the next case typo becomes a non-event instead of a silent bot lobotomy (the class that caused §1's two bugs).
  • Per-unit-type telemetry (9392540c) and +tests/docs across the window.
  • Fires/artillery-cycle design doc (39111b17) — documentation only, no gameplay change; a forward design for residual fire-support gaps.
Benchmark caveat. Because Stable itself changed this window (§1), any Experimental-vs-Stable win-rate impression from before 08-02 is invalid. A benchmark re-baseline is queued but user-gated (multi-test grant required) — until it runs, treat cross-profile comparisons as anecdotal.
