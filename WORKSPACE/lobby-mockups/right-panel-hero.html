Sized for 1440p — the right column is huge

At a 2560 × 1440 fullscreen lobby the right column gets ~1248 × 880 px — roughly 2.6× wider than the cramped 480px preview in the first mockup. That changes what "hero metrics" can be: instead of 2×2 stacks, every economy value can sit in one big horizontal row, and match settings can run inline next to world toggles.

All five variants below start from D ("hero metrics"). Each rearranges the same content — Economy → Match → World, then Active Changes and Preset — at full 1440p width. The gray left panel is a placeholder for the map + players column (also 1248 wide).

If your browser window is narrower than 2560px, scroll horizontally inside each frame to see both columns.

D0Baseline · same vocabulary, properly wide

The original "hero metrics" idea, just stretched to the actual column width. Economy becomes a 4-up row of big metric cards. Match drops below as a 3-up row of compact line rows. World spreads its toggles horizontally as pills. Active Changes and Preset live in a sticky footer.

Closest to the original D — easiest to port. The hero-card vocabulary stays the same, just used at proper scale.

D1Magazine · featured + secondary metrics

Visual hierarchy: Starting Cash is the most-changed value in skirmish, so it gets a feature card (1.6× width, larger numerals) and the other three economy values sit next to it in normal scale. Match keeps the inline-row treatment; World keeps the pill row. Reads like a dashboard with one "headline" metric per section.

Useful when one value naturally dominates — Starting Cash is probably the most-twiddled setting before launch. Feature card is a CSS gradient + larger font; both translate to in-game with a thicker ColorBlock + a larger Label font.

D2KPI strip · stats up top, controls below

Two-tier layout. Top: a single Economy "KPI strip" — four numeric values in one panel with vertical dividers (looks like a stock-ticker or analytics board). Bottom: three side-by-side columns for Match, World, and one spare slot. Active Changes + Preset run as the sticky footer. Cleanest separation of "values you watch" from "controls you set".

The KPI strip emphasises that economy values are read more than edited. Tab once to drill into each. Spare column at the right side could later hold extra match metadata (player count, faction balance, etc).

D3Sidebar nav · jump-to-section + summary

Skill-tree pattern. Left rail (220px) lists the three sections with item counts and a small badge if anything is changed. Below the nav, a "Live Summary" card surfaces the most relevant active changes so the host can see them while editing a different section. Main area is the same hero-cards-then-lines pattern as D0.

Scales nicely if more sections appear later (just add nav items). The sidebar summary is real: the user always sees their changes without having to scroll to Active Changes.

D4All hero · every option is a metric card

Maximum visual consistency. Every setting — dropdown, toggle, value — gets the same hero-card treatment in a 4-wide grid. Toggles render as cards with a switch in the top-right corner. The grid auto-flows; sections are just bold dividers between groups of cards. Reads as a "settings dashboard" — every value feels equally weighted and clickable.

Best for at-a-glance review of every setting. Risks visual monotony at scale — could later differentiate sections with subtle bg tints. Strongest "modern app" feel of the five.
