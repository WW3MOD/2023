## 1. Open work and the next concrete step

**Track #2 — AA units stand down against a live target (the user's "AA doesn't autotarget behind trees" report).** Foliage was a coincidence; reproduced with no trees and no fog.

Cause: units write a shared "damage already inbound" tally so they don't all shoot one target. MANPAD does 3000 damage against a 600-HP Halo, so a single missile records ~500 against a threshold of 100 — five kills' worth. Every other AA hard-skips the target until it decays.

Still open at `35876332`:
- `EstimatePercentDamage` (`engine/OpenRA.Mods.Common/Traits/AutoTarget.cs:1505-1557`) still returns `totalDamage * 100 / health.MaxHP` with **no cap** — the 5× overshoot is intact.
- The hard overkill skip is still a `continue` at `:1364-1365`, `OverkillThreshold = 100`.
- The warhead loop at `:1530-1554` applies `Penetration` and `Versus` but still never checks `IsValidAgainst`, so the latent `ValidTargets` over-count survives. Latent today (the templates that would trigger it — `^LargeExplosionEffectsAir` / `^HugeExplosionEffectsAir` — are inherited by nothing) but it is a strictly worse version of the same bug.
- `BreakOffCondition = "critical-damage"` (`:232`) is still a hard skip at `:1371-1372`, still bypassable only by force-attack.

What DID land upstream and does **not** close this: `wt/autotarget-preempt` (`68b627ce`) added a *soft* overkill penalty before the hard skip — `SoftOverkillThreshold = 50` / `SoftOverkillScale` at `:1439` — which de-prioritises a partially-committed target in the ranking. It reduces how often the hard skip is reached but does not remove the stand-down and does not touch the arithmetic.

**Next concrete step** (unchanged, and it composes with the soft penalty):
1. Clamp each shooter's contribution to one kill's worth in `MarkTargetForAttack` / `EstimatePercentDamage` (`:1505`, `:1565-1572`). Per-shooter, not a total cap — see §4 for why that changed.
2. Fix the `ValidTargets` omission in the same pass (`:1530-1554`).

Anything touching the arithmetic changes targeting for both bot profiles — allowed, but the `@stable` baseline must be re-taken and the commit must say so.

## 4. Transcript-only knowledge

Also written to the manager log. The load-bearing item:

**My recommendation changed mid-investigation, and the reasoning matters more than the conclusion.** I originally favoured capping the *total* accumulator — it fixes the overshoot and any runaway in one line. Then the cadence measurement showed **ordinary firing does not re-apply the tally**: the lead shooter fired eight times at a strict 200-tick `BurstWait` and the other three AA still joined on schedule. So the indefinite/runaway case needs an external feeder that does not arise naturally. That removes the main argument for the blunt total-cap, and the safer **per-shooter clamp** becomes sufficient while preserving real information when many units genuinely commit to something huge.

**Measured severity, for whoever verifies the fix:**
- ~10 s stand-down for a single commitment.
- ~34 s for four AA to all engage one helicopter — each joiner reloads the tally, so a battery **serialises** at ~185-tick spacing, trickling in one at a time.
- That serialisation only exists where the claim exceeds damage actually landed (misses, or the `ValidTargets` over-count). Unbounded only when externally fed.

**Process lessons from this window:**
- A recon's diagnosis is a HYPOTHESIS. Buy the measurement before briefing an implementer off it — two confident, well-cited recon diagnoses were each REFUTED by a single test run on track #2.
- Brief test workers to report a THIRD outcome when the data fits neither predicted branch. The unpredicted outcome was the valuable one both times.
- Reviewers earn their cost: all four branches came back FIX, and the defects were real — an attend order forcible onto enemies (walking an unarmed medic into enemy lines), and a stall guard benching the ally a parked medic was escorting, shipped inside the fix meant to stop exactly that.
- **Three of the user's four reports shared ONE root shape**: an activity that cannot do its job and does not know to stop (dry unit aims forever; suppressed medic aims forever). Check that shape first on any "unit just stands there" report.
- Two harness traps found and recorded in DISCOVERIES: a setup guard that asserts its own local variable cannot fail and turns a null result into plausible numbers; and overriding a warhead *replaces* the node, so an omitted field reverts to the **engine** default, producing a confident `pass` about a world that was never built.

**Benchmark note carried by #1 (`bd7b6bb2`), easy to under-state:** the disclosure is not "bots issue the same orders". Dry units now become *idle*, which feeds every idle-triggered trait and `IsIdle`-gated bot census that never saw them before — and `WithInfantryBody.TickIdle` draws `SharedRandom` twice per idle transition. The behaviour change is local; the RNG consequence is global. Re-take the baseline; do not diff replays across that commit.
