What was actually wrong— in the order it hits you

The panel starts with no heading and grows one two-thirds down

The first thirteen options have no section header at all — "OPTIONS" is the panel's own title, not a group — and then GAME RULES and OTHER appear with accent rails. That is not a layout choice: LobbyOptionsLogic.cs:378-379 skips headers for the Common half and :405 draws them for the Advanced half, and this panel renders both halves in one scroll. So the split you are seeing is an internal category boundary leaking through as a visual one.

"Other" is the code admitting defeat

GetSection (:197-200) drops anything not listed in OptionSection into a bucket literally named Other. Three options land there — and one of them, Nuclear Ceiling, is the fourth dropdown of the DEFCON feature, on the same trait as the three under Game Rules. It is stranded only because :187-189 lists mode/start/pace and forgets the ceiling.

Doomsday is one feature cut in half

Doomsday Clock is the match timer (timelimit, relabelled at world.yaml:658-659) — it sets when the match ends. The Doomsday checkbox is a different trait that decides what happens at that moment: on, the map is destroyed by a nuclear salvo and the frozen high score wins; off, it ends on score alone. They currently sit at opposite ends of the panel, and the checkbox does nothing at all while the clock reads "No limit". Put together, each explains the other.

The greyed-out ones are not locked — they are unimplemented

This is the question the panel most badly fails to answer. Friendly Fire and Powers Enabled are constructed with locked: false (LobbyDummyOptions.cs:209-219); you can still click them and the change still syncs. They are grey because every option that trait yields gets Placeholder = true (:35-39), and LobbyOptionsLogic.cs:462 dims the label only — which is exactly why the tick beside the grey text still looks fully bright and reads as "on but forbidden". The four DEFCON dropdowns are dimmed the same way. Today the only way to learn any of this is to hover; the proposal says it on the face of the panel, with (not wired) beside the option and a — not yet wired suffix on a section that is entirely placeholder.

Ordering inside a section cannot currently be controlled

RenderFlatOptions draws all checkboxes and then all dropdowns (:429, :476), so DisplayOrder only sorts within each run. That is why Game Mode / Start At / Escalation Pace appear below the nuclear checkboxes in Game Rules despite sorting after them, and it is the mechanical reason the order "looks arbitrary". The proposal renders in true DisplayOrder, flushing a part-full row when the control type changes — which is what lets Match lead with its dropdown and Battlefield lead with Starting Units.

Proposed tooltips— title, then what it does in play

Every option gets a two-part description: the first line becomes the tooltip title, the rest the body (ResolveTooltip, :202-223). Most options do have a description today, but nearly all are a single line, which renders as a bold title with an empty body — so the tooltip repeats the label and says nothing.

Calls I made that you may want to overrule

1. Nothing is deleted. Two earlier mockups of yours (lobby-settings-v3.html, defcon-lobby-options.html) solve this panel by removing controls — folding the three nuclear checkboxes into one "Nuclear Release", dropping the Doomsday Clock, turning Sandbox into a Game Mode. Both end on open questions you never answered. I have deliberately not resolved those here: this change regroups and explains what ships today. If you want the smaller control set, that is a feature change and should be its own piece of work.
2. Six sections, not four. Each is one or two rows, so the whole panel is readable without opening anything. The alternative is fewer, fatter groups (Match + Nuclear + World + Developer). I preferred more headings because a heading is the only thing on this panel that tells you what a control is for.
3. "Escalation" is shown but marked not-wired. All four of its dropdowns are placeholders — Game Mode defaults to Skirmish and the whole feature currently changes nothing a player can see. I kept the section visible with an honest suffix rather than hiding it. Hiding it entirely is a defensible alternative and is one line.
4. Friendly Fire sits under Battlefield, not Arsenal. It is unimplemented either way, so this is a guess about what it will mean when it ships.
5. Sandbox is filed under Developer. Your v3 mockup made it a Game Mode, on the grounds that it exists to ignore every other rule. That is the better long-term answer; Developer is the honest short-term one, since today it is a checkbox you can combine with anything.
6. The MATCH / ADVANCED tab split could not be kept. It no longer exists: LobbyLogic.cs:599-605 hides the tab strip unconditionally — "Old global tab strip (Match / Advanced / Music / Servers) is gone… The tab containers stay in the YAML but never become visible." Everything renders in this one scroll, which is why the headerless-then-headed split reads as a mess. The Common/Advanced category still exists in code and still decides what the in-game info panel shows, so it is kept — it just no longer changes how this panel is drawn.
