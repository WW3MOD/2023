Accumulated rank — buy-menu overlay

Off-map reserves accrue veterancy for every unit type over time. The buy button has to say, at a glance and without a hover, how many free ranks of each tier are waiting — because buying spends the highest one first, the top tier is what the player actually gets on the next click.

Why these are line strokes and not glyphs or sprites. A worker found earlier today that engine/mods/common/FreeSansBold.ttf ships no Geometric Shapes block — U+25C6 and neighbours map to glyph 0 and render as nothing, silently, with the trait working perfectly. There is a matching pitfall for sequence names the mod does not ship. So every chevron below is drawn with RgbaColorRenderer.DrawLine(points, width, colour) — the same primitive the existing lime auto-build stripe already uses at ProductionPaletteWidget.cs:778, chosen there for exactly this reason. A polyline cannot resolve to nothing. Only the count digits use a font, and they reuse TinyBold, already proven to render digits by the queue badge at ProductionPaletteWidget.cs:807-822.

What the strip encodes

One entry per tier currently held. A tier with zero stock draws nothing at all — an empty button stays completely clean, which matters because most buttons are empty most of the time. Each entry is a stack of N chevrons for tier N, so the glyph itself names the rank the way military insignia does, and a count digit sits to its right when more than one of that tier is held.

The strip is anchored bottom-left because that is the only corner of this button nothing else claims: the queue badge owns top-right (countRightAnchor = IconSize.X - 3, ProductionPaletteWidget.cs:199), the ready/hold/time text owns the centre, and the auto-build stripe owns a 3 px column on the far left, which the strip starts clear of.

Caps are 3 / 2 / 1. So the widest case this strip ever has to draw is the full 3× rank-1, 2× rank-2, 1× rank-3 — the last state in the gallery. That is the layout budget; nothing wider can occur.
