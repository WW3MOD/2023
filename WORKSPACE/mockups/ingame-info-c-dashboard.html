Direction C — “Dashboard”

The actual reimagining. The flat six-row table stops being the whole tab and becomes a standings rail on the left; selecting a row fills a detail pane on the right with that player’s army-value curve, force composition and Supply Route state. It converts the Esc menu from a roster into the thing you actually want while watching six AIs fight.

Cost: the largest of the three. A new logic class (~200 lines) driving selection state, plus reuse of LineGraphWidget and ObserverArmyIconsWidget, both of which take a GetPlayer delegate and are already wired that way in ObserverStatsLogic. No new widget types. Budget it as a multi-session piece of work, not an afternoon.

Why this is worth considering despite the cost: the observer HUD already has all of this — eight stat modes, income and army graphs, army icons. But it lives in a 240px strip at the top of the screen that is only visible while you are not in the menu. The Esc menu is where you go to study the match, and today it shows strictly less than the HUD you just covered up. C closes that gap by reusing the HUD's own widgets rather than inventing anything.

Feasibility notes, honestly stated

OK The graph is LineGraphWidget, already fed from PlayerStatistics.ArmySamples (PlayerStatistics.cs:43) by the observer's ARMY_VALUE_GRAPH.
OK Force composition is ObserverArmyIconsWidget, which takes a GetPlayer delegate — pointing it at the selected player is the same call the observer HUD already makes.
OK Selection is a ScrollItem OnClick setting a captured field; ObserverStatsLogic already does click-to-act on player rows (it centres the viewport on their base).
CARE The Supply Route block needs a lookup the codebase does not currently do from this panel. SupplyRouteContestation is an actor trait on SUPPLYROUTE (mods/ww3mod/rules/ingame/structures.yaml:303), not a player trait, so the logic must resolve world.ActorsHavingTrait<SupplyRouteContestation>() filtered by owner. Cheap, but it is new code and it is the one part of C I would build first to de-risk.
CARE 268px is not much width for a detail pane. Everything above fits, but there is no room to add a ninth thing later without a scroll panel.
